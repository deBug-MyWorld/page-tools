0. 安装前准备

0.1 本机检查

  • 系统版本：Windows 10（1903+）或 Windows 11，64 位系统（本手册不适用于 32 位）
  • 磁盘空间：至少预留 10 GB 空闲空间（全部工具装完约占 3~4 GB，其余留给后续项目和依赖缓存）
  • 安装路径原则：本手册所有工具统一安装到 D 盘 D:\dev\ 目录下，避免占用 C 盘空间导致系统盘膨胀。安装前先在 D 盘建好 D:\dev 文件夹
  • 管理员权限：安装过程部分步骤需要管理员权限，建议先右键「此电脑」→「管理」→ 查看当前用户是否在 Administrators 组
  • 卸载旧版本：如果电脑上已装有旧版 JDK 8/11、旧版 Node、Anaconda 等，建议先卸载干净再装新的，避免 PATH 冲突（见第 10 章排查 10.5）
  • 网络：确保能访问外网；若在公司办公网下载慢，各章节都提供了国内镜像备选地址

0.2 快速检查命令

按 Win + R 输入 cmd 回车打开命令行，逐条输入以下命令，看哪些已装过：

java -version
mvn -v
git --version
conda --version
nvm version

提示：命令不存在会提示「不是内部或外部命令」，属正常现象，按对应章节安装即可。

1. Oracle JDK 21 安装

JDK 21 是 Java 长期支持版本（LTS），公司后端项目统一基于 JDK 21 开发。JDK 全称 Java Development Kit，安装后自带编译器（javac）和运行环境（java），后续 Maven、IDEA、SpringBoot 项目全部依赖它。

1.1 下载 JDK 21

渠道地址 / 操作说明
官方（首选）Oracle 官网 https://www.oracle.com/java/technologies/downloads/ → 选「JDK 21」→ Windows x64 → 下载 jdk-21_windows-x64_bin.exe下载需在页面点「Accept License Agreement」，约 180MB
镜像备选华为云 https://repo.huaweicloud.com/java/jdk/ → 找 21.0.x 目录 → 下载 jdk-21_windows-x64_bin.exe办公网下载慢时用，速度更快

1.2 方式一：图形化安装（推荐新手）

  1. 双击安装包

    双击下载好的 jdk-21_windows-x64_bin.exe，若弹 UAC 提示，点「是」允许。

  2. 一路 Next

    到选择安装路径页面时，点「更改」将路径改为 D:\dev\jdk-21（不要装在默认的 C 盘 C:\Program Files\Java）。改好后点「下一步」继续，其余一路 Next。

    注：请记住你实际安装的路径，后续配置环境变量要用到。以下示例均以 D:\dev\jdk-21 为准。

  3. 完成

    点「关闭（Close）」结束向导。接着看 1.4 节配置环境变量。

1.3 方式二：命令行安装（winget，可选）

若你习惯命令行，可用 Windows 自带包管理器 winget 一键安装（需 Windows 10 1709+ / Windows 11）：

winget install Oracle.JDK.21

安装完成后同样需要手动确认环境变量（见 1.4 节）。winget 默认装到 C 盘，建议装完后将目录移动到 D:\dev\jdk-21，或直接用图形化方式安装到 D 盘。

1.4 配置环境变量（关键步骤）

  1. 打开系统环境变量

    右键「此电脑」→「属性」→「高级系统设置」→「环境变量」。也可以 Win + R 输入 sysdm.cpl 直接打开。

  2. 新建 JAVA_HOME

    在「系统变量」区域点「新建」，变量名输入 JAVA_HOME，变量值输入 D:\dev\jdk-21（按你实际安装路径填），确定。

  3. 配置 Path

    在「系统变量」里找到 Path，双击打开 → 点「新建」→ 输入 %JAVA_HOME%\bin → 一路「确定」关闭所有窗口。

    注意：所有弹出的窗口都要点「确定」保存，直接关 × 等于没配。

1.5 验证安装

重新打开一个新的命令行窗口（必须新开，旧窗口不会刷新环境变量），输入：

java -version
javac -version

看到类似下面的输出，表示安装成功：

java version "21.0.x" 2026-xx-xx LTS
Java(TM) SE Runtime Environment (build 21.0.x+xx)
Java HotSpot(TM) 64-Bit Server VM (build 21.0.x+xx, mixed mode, sharing)

常见报错：若提示「java 不是内部或外部命令」，说明环境变量没生效——重新检查 1.4 步骤是否全部点过「确定」，并重开命令行再试；还不行看第 10 章排查 10.1。

2. Maven 3.9.x 安装

Maven 是 Java 项目依赖管理与构建工具，公司后端项目统一用 Maven 管理依赖（Spring Boot 等）。Maven 3.9.x 要求 JDK 8 以上，我们已装 JDK 21，完全兼容。

2.1 下载 Maven

渠道地址 / 操作说明
官方（首选）https://maven.apache.org/download.cgi → 下载 Binary zip archive 版本 apache-maven-3.9.x-bin.zip（约 10MB）需选 3.9.x 系列
镜像备选阿里云 https://mirrors.aliyun.com/apache/maven/maven-3/ → 进最新 3.9.x 目录下载同名 zip办公网更快

2.2 解压到固定目录

  1. 解压 zip

    将 apache-maven-3.9.x-bin.zip 解压，例如解压到 D:\dev\apache-maven-3.9.x（建议统一放 D:\dev 目录，方便管理）。

  2. 确认目录结构

    解压后进入该目录，应能看到 bin、conf、lib 等文件夹，其中 bin 下有 mvn.cmd 文件即正确。

2.3 配置环境变量

  1. 新建 MAVEN_HOME

    「此电脑」→「属性」→「高级系统设置」→「环境变量」→ 系统变量 → 新建：变量名 MAVEN_HOME，变量值 = 你的 Maven 解压路径（如 D:\dev\apache-maven-3.9.9）。

  2. 配置 Path

    编辑系统变量 Path，新增 %MAVEN_HOME%\bin，全部点「确定」。

2.4 配置阿里云镜像（settings.xml，重要）

Maven 默认从中央仓库下载依赖，在国内很慢。建议直接替换为阿里云镜像。Maven 的配置文件位于 解压目录\conf\settings.xml，用记事本打开，找到 <mirrors> 标签（通常在 146 行附近），把下面内容粘贴进去：

<!-- 替换默认 mirror 为阿里云镜像，加速依赖下载 -->
<mirrors>
  <mirror>
    <id>aliyunmaven</id>
    <mirrorOf>central</mirrorOf>
    <name>阿里云公共仓库</name>
    <url>https://maven.aliyun.com/repository/public</url>
  </mirror>
</mirrors>

如果原来 <mirrors> 里已有内容，把旧的 <mirror> 整段删除再粘贴上面的即可（只保留一个 mirror 最干净）。

2.5 配置本地仓库目录（重要）

Maven 下载的所有依赖包默认存放在 C:\Users\你的用户名\.m2\repository，随着项目增多会占用数 GB 的 C 盘空间。建议改到 D 盘，与 Maven 放一起方便管理。

  1. 创建本地仓库目录

    在 D 盘创建文件夹 D:\dev\maven-repo（可自定义路径，建议和 Maven 放同一级目录）。

  2. 修改 settings.xml

    用记事本打开 D:\dev\apache-maven-3.9.9\conf\settings.xml，找到约第 55 行被注释的 <localRepository> 配置：

<!-- 原始内容（被注释的，大约在第 53~55 行） -->
<!-- <localRepository>/path/to/local/repo</localRepository> -->

<!-- 改为（去掉注释，填你的路径，注意用正斜杠 / ） -->
<localRepository>D:/dev/maven-repo</localRepository>

注意：路径分隔符建议用正斜杠 /（如 D:/dev/maven-repo），反斜杠 \ 在 XML 中需要写 \\ 双反斜杠，容易出错。

验证：修改后在命令行执行 mvn help:system，Maven 会下载基础插件到你配置的 D:\dev\maven-repo 目录。去该目录看是否生成了文件夹，有就说明配置生效了。

2.6 验证安装

重开命令行，输入：

mvn -v

看到类似输出即成功：

Apache Maven 3.9.9 (8e0a8c1b6a)
Maven home: D:\dev\apache-maven-3.9.9
Java version: 21.0.x, vendor: Oracle Corporation
Java home: C:\Program Files\Java\jdk-21
...

重点看 Java version 是否为 21。若显示的 Java 版本不对，说明系统里有多个 JDK 抢占了 PATH，见第 10 章排查 10.2。

3. Git for Windows 安装

Git 是代码版本管理工具，公司代码统一存放在 Git 仓库（如 Gitee / GitLab）。Windows 上安装「Git for Windows」会自带 Git Bash 终端，最常用。

3.1 下载 Git

渠道地址 / 操作说明
官方（首选）https://git-scm.com/download/win → 下载 64-bit 版 Git-2.4x.x-64-bit.exe官网下载较慢时用镜像
镜像备选清华镜像 https://mirrors.tuna.tsinghua.edu.cn/github-release/git-for-windows/git/ → 选最新版 → 下载 Git-...-64-bit.exe国内速度快

3.2 图形化安装（一路默认即可）

  1. 双击安装包

    双击 Git-2.4x.x-64-bit.exe，按提示点「Next」。

  2. 更改安装路径

    到 Select Destination Location 页面，将路径改为 D:\dev\Git（默认是 C 盘 C:\Program Files\Git），改好后点 Next。

  3. 关键选项保持默认

    出现以下页面时全部保持默认，直接 Next：

    ① Select Components（勾选默认项即可）
    ② Default branch name → 默认 master 即可
    ③ Adjusting PATH → 选中间项 Git from the command line and also from 3rd-party software（推荐）
    ④ 其余（换行符处理、凭据管理器等）保持默认

  4. 完成

    点「Install」→「Finish」。完成后桌面或开始菜单会出现 Git Bash。

3.3 命令行安装（winget，可选）

winget install --id Git.Git -e

3.4 首次使用配置（必须做）

打开 Git Bash（开始菜单搜索 Git Bash），配置你的用户名和邮箱（会写入每次提交记录，必须用真实姓名和公司邮箱）：

git config --global user.name "你的姓名"
git config --global user.email "你的邮箱@telecom.cn"

3.5 生成 SSH 密钥（推荐，拉取私有仓库用）

在 Git Bash 中执行（一路回车即可，口令可留空）：

ssh-keygen -t ed25519 -C "你的邮箱@telecom.cn"

然后查看公钥内容，复制后粘贴到 Gitee / GitLab 的「SSH 公钥」设置里：

cat ~/.ssh/id_ed25519.pub

若公司仓库用 HTTP 方式（带账号密码），可跳过本步骤。

3.6 验证安装

git --version
git config --global user.name

看到 git version 2.4x.x.windows.1 及刚才配置的姓名即成功。

4. Miniconda 安装

Miniconda 是轻量级 Python 环境管理工具，可创建相互隔离的 Python 虚拟环境（项目 A 用 py3.10，项目 B 用 py3.11，互不干扰）。公司内部 Python 项目、AI 相关脚本建议统一用它管理。

4.1 下载 Miniconda

渠道地址 / 操作说明
官方（首选）https://docs.conda.io/en/latest/miniconda.html → 选 Windows x86_64 → 下载 Miniconda3-latest-Windows-x86_64.exe约 80MB
镜像备选清华镜像 https://mirrors.tuna.tsinghua.edu.cn/anaconda/miniconda/ → 下载最新 Miniconda3-py311_...-Windows-x86_64.exe办公网更快

4.2 安装（注意勾选项）

  1. 双击安装包

    双击 Miniconda3-latest-Windows-x86_64.exe，Next。

  2. 选择安装位置

    将路径改为 D:\dev\miniconda3（默认是 C 盘 C:\Users\你的用户名\miniconda3，不建议装 C 盘）。

  3. 关键勾选项（必看）

    到 Advanced Installation Options 页面，勾选第一项 Add Miniconda3 to my PATH environment variable（把 conda 加入环境变量），其余保持默认 → Install。

    如果不勾，conda 命令只能在 Anaconda Prompt 里用，很麻烦。

  4. 完成

    安装结束后建议重开一个命令行窗口。

4.3 配置国内镜像源（加速下载）

打开命令行，依次执行（任选其一，推荐清华源）：

# 清华源（推荐）
conda config --add channels https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/main/
conda config --add channels https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/free/
conda config --set show_channel_urls yes

配置后执行 conda clean -i 可清索引缓存加速。

4.4 创建项目专用 Python 环境（推荐）

日常开发不要直接用 base 环境，给每个项目建独立环境：

# 创建 Python 3.11 环境，名字叫 py311
conda create -n py311 python=3.11 -y

# 激活该环境（每次进项目前先激活）
conda activate py311

# 验证当前 Python 版本
python --version

4.5 验证安装

conda --version
conda env list

看到 conda 23.x.x 和环境列表即成功。激活环境后命令行前缀会变为 (py311)。

注意：conda 首次激活可能较慢属正常；若提示 conda 不是内部或外部命令，多半是没勾 PATH 或没重开窗口，见第 10 章排查 10.3。

5. NVM（nvm-windows）+ Node.js 安装

NVM（Node Version Manager）用于管理多个 Node.js 版本，公司前端项目可能用到不同 Node 大版本（如 18 / 20 / 22），装好 NVM 后可随时切换。Windows 上使用的是 nvm-windows（注意与 Linux/macOS 的 nvm 不是同一个软件）。

5.1 下载 nvm-windows

渠道地址 / 操作说明
官方（首选）https://github.com/coreybutler/nvm-windows/releases → 下载 nvm-setup.exeGitHub 慢时用镜像
镜像备选国内加速（如 ghproxy）或清华镜像搜索 nvm-windows，下载 nvm-setup.exe—

5.2 安装 nvm-windows

  1. 先卸载已有 Node（如果有）

    如果电脑已装过 Node.js，先去「控制面板 → 程序和功能」卸载干净，否则会冲突。

  2. 运行 nvm-setup.exe

    双击安装，Next。安装路径改为 D:\dev\nvm（默认在 C 盘 AppData 下，建议改到 D 盘）。注意路径里不要有中文。安装过程中会提示选择 Node.js 的 symlink 路径，改为 D:\dev\nodejs。

  3. 完成

    Finish 后重开命令行，执行 nvm version 应看到版本号。

5.3 安装 Node.js LTS 版本

# 查看可安装版本
nvm list available

# 安装最新 LTS（如 22.x，公司统一用 LTS 即可）
nvm install 22.16.0

# 切换到该版本（Windows 下 use 必须以管理员身份运行命令行）
nvm use 22.16.0

重要：nvm use 需要管理员权限。若提示权限不足，请右键命令行「以管理员身份运行」再执行。

5.4 配置 npm 国内镜像（加速）

npm config set registry https://registry.npmmirror.com

5.5 验证安装

node -v
npm -v

分别看到 v22.x.x 和 10.x.x 即成功。切换版本用 nvm list 查看已装版本，nvm use 版本号 切换。

6. IntelliJ IDEA 安装

IntelliJ IDEA 是 Java 开发主力 IDE，公司后端日常编码都在它上面。社区版（Community）免费够用，旗舰版（Ultimate）需授权。新同事装 Community 版即可。

6.1 下载

渠道地址 / 操作说明
官方（首选）https://www.jetbrains.com/idea/download/ → 下拉选 Community（免费）→ 下载 ideaIC-2024.x.exe约 700MB
命令行执行 winget install --id JetBrains.IntelliJIDEA.Community -e自动安装到默认路径

6.2 安装

  1. 运行安装包

    双击 ideaIC-2024.x.exe，Next。安装路径改为 D:\dev\IntelliJ IDEA Community Edition（默认在 C 盘 C:\Program Files 下）。

  2. 勾选关联项

    到 Installation Options 页面，建议勾选：
    ① 64-bit launcher（创建 64 位快捷方式）
    ② Add "Open Folder as Project"（右键菜单支持）
    ③ .java（关联 java 文件）
    ④ Add launchers dir to the PATH（加入环境变量，可选）

  3. 完成

    Install → Finish。首次启动会提示选择主题（Darcula 深色 / Light 浅色），按个人喜好选即可。

6.3 配置项目 JDK（指向 JDK 21）

  1. 打开项目结构设置

    菜单栏 File → Project Structure → SDK（中文版：文件 → 项目结构 → SDK）。

  2. 添加 JDK 21

    点 + → JDK → 选择 JDK 安装目录 D:\dev\jdk-21 → 确定，IDEA 会自动识别版本 21。

  3. 设为项目 SDK

    在 Project Structure 顶部「Project SDK」下拉选择刚加的 21，应用（Apply）确定。

6.4 配置 Maven（指向本地 Maven 与 settings.xml）

  1. 打开 Maven 设置

    File → Settings → Build, Execution, Deployment → Build Tools → Maven。

  2. 指定 Maven home

    「Maven home path」选择你的解压路径 D:\dev\apache-maven-3.9.9（不用 bundled 的）。

  3. 指定 settings.xml

    勾选「User settings file」的「Override」，选择 D:\dev\apache-maven-3.9.9\conf\settings.xml → Apply → 确定。

验证：打开任意 Maven 项目，右下角 Maven 面板能看到依赖正常下载即配置正确。若下载慢，确认 settings.xml 已配阿里云镜像（见 2.4）。

7. Visual Studio Code 安装

VS Code 是轻量级、插件丰富的编辑器，前端、Python、脚本、配置文件编辑都用它。配合 NVM / Miniconda 开箱即用。

7.1 下载与安装

渠道地址 / 操作说明
官方（首选）https://code.visualstudio.com/ → 下载 Windows x64 System Installer VSCodeSetup-x64-x.x.x.exe建议选 System 版（全用户）
命令行执行 winget install --id Microsoft.VisualStudioCode -e自动安装
  1. 运行安装包

    双击安装，Next。安装路径改为 D:\dev\Microsoft VS Code（默认在 C 盘）。到「选择附加任务」页面，建议勾选：
    ① 将「通过 Code 打开」操作添加到资源管理器上下文菜单
    ② 将 Code 注册为支持的文件类型编辑器
    ③ 添加到 PATH（重启后生效）

  2. 完成

10. 常见问题排查

把最常踩的坑集中放这里，按编号查。多数报错都是环境变量没生效或路径填错。

10.1 提示「java 不是内部或外部命令」？

环境变量没生效。检查三件事：① 系统变量里 JAVA_HOME 路径对不对（指向 jdk-21 根目录）；② Path 里有没有 %JAVA_HOME%\bin；③ 必须重开一个新命令行窗口，旧窗口不会刷新。若改完还不行，把 C:\Program Files\Java\jdk-21\bin 直接加到 Path 里（绝对路径）再试。

10.2 mvn -v 显示的 Java 版本不是 21？

系统里有多个 JDK 抢占了 PATH。打开环境变量，把 JAVA_HOME 的顺序在 Path 中提到最前；或检查是否有别的 JAVA_HOME（如用户变量）覆盖了系统变量。也可在命令行执行 where java 看实际用的是哪个 java.exe。

10.3 「conda 不是内部或外部命令」？

安装时没勾「Add Miniconda3 to my PATH」。两个办法：① 重装时勾上；② 手动把 C:\Users\你的用户名\miniconda3\Scripts 和 C:\Users\你的用户名\miniconda3 加到 Path，重开窗口。

10.4 nvm use 提示权限不足 / 切换没生效？

Windows 下 nvm use 需要管理员权限。右键命令行「以管理员身份运行」再执行。另外确认安装 nvm 前已卸载旧的独立 Node，否则会冲突。

10.5 装新版工具前旧版卸不干净导致冲突？

① 控制面板卸载旧软件；② 删除残留目录（如旧 C:\Program Files\Java\jdk-11）；③ 清理环境变量里旧的相关项（旧 JAVA_HOME、旧 Path 项）；④ 重开命令行执行 where java 确认没指向旧版本。

10.6 Maven / npm 下载依赖特别慢或失败？

没配国内镜像。Maven 确认 settings.xml 配了阿里云镜像（2.4）；npm 执行 npm config set registry https://registry.npmmirror.com，再 npm config get registry 确认。

10.7 环境变量改了但命令行还是旧的？

必须重新打开一个新的命令行窗口，已打开的窗口不会重新读取环境变量。改完变量后也可重启资源管理器（任务管理器里重启「Windows 资源管理器」进程）确保生效。

10.8 winget 提示「未识别命令」？

winget 是 Windows 10 1709+ 自带，旧系统可能没有。可去 Microsoft Store 搜索「应用安装程序」安装，或直接用各章节的图形化安装方式。

10.9 下载安装包时浏览器报安全拦截？

Edge/Chrome 对 .exe 有时弹拦截提示，点「保留」即可。若被 SmartScreen 拦，点「更多信息」→「仍要运行」。请认准官方域名下载，避免第三方站点捆绑安装。

10.10 IDEA 中 Maven 依赖一直红/下载失败？

确认 IDEA 用的 settings.xml 是你配了阿里云镜像的那个（见 6.4）。可在 IDEA 右下 Maven 面板点刷新按钮重下；若个别依赖失败，删本地仓库里对应目录再重新构建。
